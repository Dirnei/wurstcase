# Design

## Context

See proposal.md (Why) and the two delta specs. Current state: the UI is `App.svelte` with `Header`
and `PlayTime`; there is no routing. All text goes through `src/i18n/{de,en}.json` with a
key-parity test. The container runs nginx as uid 101 from `nginxinc/nginx-unprivileged`. That
image runs every script in `/docker-entrypoint.d/` at start-up as uid 101. `/tmp` is writable,
`/usr/share/nginx/html` is not. The game loop runs from `main.ts`, independent of which view is
shown.

## Goals / Non-Goals

**Goals:**
- Operator details changeable per deployment without rebuilding the image.
- Legal texts are data with DE/EN parity, like all other content.
- Privacy statements are true by construction: no cookies, no third-party hosts, no full IPs.

**Non-Goals:**
- Changes to `src/game/`: no game-state files and no content entries are added or changed.
- A generic router. Two hash routes are enough.

## Decisions

### Operator details: runtime `legal.json`, generated by an entrypoint script

```
docker/40-legal-json.sh   runs at container start (uid 101), writes /tmp/legal/legal.json
docker/nginx.conf         location = /legal.json → alias /tmp/legal/legal.json, Cache-Control: no-cache
public/legal.json         the same placeholder defaults, used by `npm run dev` and plain builds
```

`legal.json` shape: `{ name, street, postalCode, city, country, email, hostingProvider }`, all
strings.

- **Why runtime, not build-time:** the user wants to set the details via compose environment
  variables. Build-time (`VITE_*`) would bake them into the JS bundle and require a rebuild for
  every change.
- **Why a script, not nginx `envsubst` templates:** templates would inline raw values into a
  config or JSON string, and a `"` in a name would break it. The script JSON-escapes each value
  (backslash, double quote; control characters removed) with `sed`/`tr`, which are present in the
  alpine image.
- **Defaults and the placeholder warning:** `compose.yaml` passes each variable as
  `LEGAL_X: ${LEGAL_X:-<placeholder>}`, so the defaults are visible where the operator sets
  values. The placeholders are Max Mustermann, Musterstraße 1, 12345, Musterstadt, Deutschland,
  kontakt@example.com, and "Muster Hosting GmbH, Musterweg 2, 12345 Musterstadt". The script
  warns when a value is empty or contains `Muster` or `example.com`. It checks markers rather than
  a second copy of the defaults, so the list lives in one place (compose) and `public/legal.json`
  mirrors it for dev.
- The README recommends setting real values in a `.env` file next to `compose.yaml`, which
  Compose loads automatically. `.env` is added to `.gitignore` so personal data never lands in
  git.

### Anonymized access log

At the top of `docker/nginx.conf`, which is included in the `http` context:

```
map $remote_addr $remote_addr_anon {
    ~^(?P<a>\d+\.\d+\.\d+)\.\d+$          $a.0;
    ~^(?P<a>[0-9a-f]*:[0-9a-f]*:[0-9a-f]*):  $a::;
    default                                 0.0.0.0;
}
log_format anonymized '$remote_addr_anon - [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"';
```

The server block sets `access_log /var/log/nginx/access.log anonymized;`. This overrides the
image's `main` format, which would also log `X-Forwarded-For`. Truncating in nginx rather than in
a log processor means the full IP is never written anywhere by this container. A reverse proxy in
front, in production, is the host's responsibility and is named in the privacy text under
Hosting.

### Legal texts as structured i18n content

```
src/legal/texts.de.ts / texts.en.ts   LegalDocument = { title, note?, sections: [{ id, heading, paragraphs[] }] }
src/legal/operator.ts                 parseOperatorDetails(json) → OperatorDetails | null (pure, tested)
src/legal/route.ts                    routeFromHash('#impressum') → 'impressum' | 'datenschutz' | 'game'
src/ui/legal.svelte.ts                fetch('./legal.json', { cache: 'no-cache' }) once, reactive result
src/ui/Footer.svelte                  two links: href="#impressum", href="#datenschutz"
src/ui/LegalPage.svelte               renders a LegalDocument, fills {name}, {email}, … from operator details
src/App.svelte                        shows the game view or LegalPage based on the current route
```

- Long legal prose does not fit well as flat `app.*` keys in `de.json`/`en.json`. It becomes typed
  documents per language, with a parity test (same section ids in both languages, same
  placeholders) mirroring the existing dictionary parity test. Short UI strings (footer labels,
  "back to the game", "details unavailable") stay in `de.json`/`en.json`.
- Paragraph text supports `{placeholders}` for operator details. The email is rendered as a
  `mailto:` link by `LegalPage`, not by embedding HTML in the text, so the content stays plain
  strings with no `{@html}`.

### Hash routes via real links

Footer entries are plain `<a href="#impressum">`. The browser handles history, so the back button
works and the URLs can be shared, with no router library. `route.svelte`-style state listens to
`hashchange`. The "back to the game" link uses `history.back()` when the previous entry was the
game, else sets the hash to empty. The game loop is untouched: `App` only swaps which view is
rendered, so play time keeps advancing.

### Proving "no cookies, no third parties"

This is verified in the browser check: record every request and assert that each is same-origin,
and assert that `document.cookie` is empty. An automated guard in the codebase would need a
browser test runner, which the project doesn't have yet (UI is verified by playing, concept 7.5).

## Risks / Trade-offs

- [Legal text is not legal advice] → The proposal names it as a draft; the author has it reviewed
  before release. Content is data, so fixes are text edits.
- [Placeholder details go live by accident] → Start-up warning in the container log, plus the
  obviously fake default values.
- [itch.io build shows placeholders] → Out of scope here; `release-v1` generates `legal.json` for
  the zip.
- [The IPv6 truncation regex misses unusual notations (e.g. `::1`)] → The `default` branch logs
  `0.0.0.0`, so an unmatched address is dropped rather than logged in full.
- [Personal data in `.env` committed by mistake] → `.env` is added to `.gitignore`.
